# HPB連携（予約メールの取り込み）設定手順

HPB（ホットペッパービューティー）の予約通知メールを、自社の予約台帳へ自動で入れるしくみです。
**取り込みだけ**です。サロンボードには何も書き込みません（枠を閉じる作業は今までどおり）。

```
サロンボード ──予約通知メール──▶ kokage.corp+hpb-<ランダム>@gmail.com（Gmail）
                                   │  Google Apps Script（5分ごと・無料）
                                   │  探す条件＝宛先（店ごとのランダムなアドレス）＋送り主（HPBのドメイン）
                                   ▼
                     アプリの受け口 /api/inbound/hpb
                        ├ 合言葉（店ごと）を確かめる
                        ├ 送り主（From のドメイン）と Gmail の認証結果（DKIM/SPF）を確かめる → だめなら「拒否」（本文は保存しない）
                        └ 予約台帳（HPBの印）＋受信ログ
```

### 送り主の確認（2026-11-08〜・監査 S2 対応）
- 受信アドレスは **店ごとにランダム**（例 `kokage.corp+hpb-7kq2m9xw4hfp@gmail.com`）。店のURL名から作る昔の形（`+hpb-kokage-gotanda`）は推測されるので使わない。**人に見せない**。
- アプリは、From のドメインが「送り主の許可リスト」（設定＞HPB連携＞3-2。空なら `salonboard.com`・`beauty.hotpepper.jp`）にあり、かつ Gmail が付けた認証結果で **DKIM（署名ドメインが送り主と同じ）か SPF が pass** のメールだけ台帳に入れます。DMARC が fail なら拒否。
- 認証結果の無いメール（古い Apps Script のまま）は、既定では **拒否** します（設定の「認証結果の無いメールは受け付けない」を外すと From のドメインだけで受けますが、おすすめしません）。
- 拒否したメールは受信ログに「拒否（送り主を確認できない）」で残ります。保存するのは送り主のドメインと理由だけ（件名・本文・名前・電話は保存しません）。再処理はできません。
- 変更・キャンセルのメールは、**予約番号が一致**し、**お名前（またはカナ）か電話が台帳のお客様と一致**し、**HPBから入った予約**のときだけ反映します。合わないときは「要確認」で止まります。ネット予約・電話予約は予約番号が同じでも触りません。
- ★**要確認**：HPB（サロンボード）の通知メールの本当の送り主は、まだ本物のメールで確かめていません。最初の通知が届いたら、Gmail で「メッセージのソースを表示」→ `From:` と `Authentication-Results:` の `dkim=pass header.i=@◯◯` を見て、そのドメインを許可リストと FROM_DOMAINS に入れてください。

## 0. 先にやること（1回だけ）
1. Supabase の SQL エディタで `supabase/migrations/0011_hpb_inbound.sql` を流す（0010 の後）。最後に「0011 OK」と出れば完了。
   - 送り主の確認の設定（許可リスト・「拒否」の記録）は `0021_security_hardening.sql`（0019 → 0020 → 0021 の順）の後に使えます。
2. Vercel → Settings → Environment Variables に **`SUPABASE_SERVICE_ROLE_KEY`** を入れる（Supabase → Settings → API の service_role key。人に見せない）。入れたら Redeploy。
   - 確認：ブラウザで `https://salon-app-alpha-seven.vercel.app/api/inbound/hpb` を開いて `"ok":true` と出ればOK（`not_configured` ならキーが入っていない）。

## 1. アプリ側（設定＞HPB連携＞つなぐ設定）
1. 「合言葉を作る」を押す → 表示された合言葉をコピー（**今だけ表示**。あとで見られません。人に見せない）。
2. 「サロンボードに登録するメールアドレス」で **「ランダムなアドレスを作る」→「保存」**（例 `kokage.corp+hpb-7kq2m9xw4hfp@gmail.com`）。黄色の「推測されやすい形です」が出ていたら必ず作り直す。
2-2. 「送り主の確認」に、HPBの通知メールの送り主のドメインを入れる（分かるまでは空＝既定のまま）。
3. 「取り込みのオン・オフ」にチェック。
4. 「対応表」タブで、HPBのクーポン名 → 自社メニューの対応を足す（同じ名前なら自動で合わせます。「試す」で確認できます）。

## 2. サロンボード側
1. サロンボード → 設定（店舗・サロン情報）→ **予約通知メールの送信先**（10件まで登録できる欄）に、上のアドレスを **1つ足す**。今のカミングスーンの受付アドレスは消さない。
   - 昔の形（`kokage.corp+hpb-<店のURL名>@gmail.com`）を登録していたら、**新しいランダムなアドレスに入れ替えて、古いほうは消す**。
2. 「+」付きのアドレスが登録できない場合は、窓口に連絡してください（別の方法：Gmail のフィルタで HPB からのメールに印を付ける形に変えます）。

## 3. Google Apps Script（kokage.corp の Gmail で）
1. https://script.google.com を **kokage.corp@gmail.com** で開く → 「新しいプロジェクト」→ 名前「HPB取り込み（◯◯店）」。
2. `tools/gas/hpb_forwarder.gs` の中身を全部貼り付けて保存。
3. 左の歯車「プロジェクトの設定」→ 下の「スクリプト プロパティ」に5つ入れる：

| プロパティ | 値 |
|---|---|
| WEBHOOK_URL | `https://salon-app-alpha-seven.vercel.app/api/inbound/hpb` |
| SECRET | 1-1 でコピーした合言葉 |
| PLUS_ADDRESS | 1-2 で保存したランダムな受信アドレス |
| FROM_DOMAINS | HPBの送り主のドメイン（カンマ区切り）。★要確認。空なら `salonboard.com,beauty.hotpepper.jp` |
| DRY_RUN | `true`（最初は試し） |

   - 前の版で入れていた **QUERY は消してください**（PLUS_ADDRESS と FROM_DOMAINS から「宛先＋送り主」の条件を自動で作ります）。自分で QUERY を入れる場合は `to:` と `from:` の両方が要ります（無いとスクリプトが止まります）。
   - **前の版のスクリプトを使っている店は、`tools/gas/hpb_forwarder.gs` の中身を新しい版に全部貼り替えてください**（新しい版だけが Gmail の認証結果を送ります。古い版のままだと全部「拒否」になります）。

4. エディタ上の関数の選択で **`listOnly`** → 実行（初回は Google の許可画面が出るので「許可」）。条件に合うメールの件名がログに出ます。
5. **`testLatest`** → 実行。一番新しいメールを「試し」で送り、アプリがどう読んだか（予約番号・日時・名前…）と **送り主の判定（`"sender":{"ok":true…}`）** がログに出ます。台帳には入りません。`ok:false` なら理由（ドメインが許可リストにない・DKIM/SPF が pass でない など）を見て、許可リスト／FROM_DOMAINS を直します。
6. 読み取りがおかしいときは、そのログ（本文の個人情報は消して）を窓口に送ってください。読み取りの調整をします。
7. 問題なければ DRY_RUN を **`false`** にして、**`installTrigger`** を1回実行 → 5分ごとに自動で動きます。
   - 止めたいとき：`removeTrigger` を実行、またはアプリの「取り込みのオン・オフ」を外す（届いたメールは受信ログに「無視」で残り、あとで「再処理」できます）。

## 4. テスト店舗で試す（HPBが無くても試せる）
設定＞HPB連携＞**テスト**（テスト店舗・オーナーだけ）→「テストメールを送る」。
本物と同じ処理で台帳に入ります。新規 → 変更 → キャンセル、ペアのクーポン、空きが無い時間（赤い印）を試せます。

## 5. ふだんの見かた
- 予約台帳：HPBの予約は「HPB」の印。空きが足りないのに入った予約は **赤い枠＋「⚠重複」**。上に「⚠ ダブルブッキングの可能性 ◯件」。予約を押して担当・時間を調整 →「調整した（印を消す）」。
- 予約台帳の「新しい予約 ◯件」ボタン：HPBの新規・変更・キャンセルと、自動で読めなかったメール（HPB要確認）が出ます。
- 設定＞HPB連携＞**受信ログ**：届いたメールすべて・読み取った内容・やったこと。「要確認（未取込）」は **手で直す**（日時・予約番号・メニューなどを入れて反映）か **再処理**。

## 6. 注意
- 本物のHPBのメールの形は、まだ確かめていません。**最初の本物のメールが届いたら、受信ログで読み取り結果を必ず確認**してください。読めない項目があれば、つなぐ設定の「読み取りの調整」に言葉を足すか、窓口に本文を送ってください。
- メールが届いてから台帳に入るまで、最大5分ほどかかります（Apps Script の間隔）。その間にネット予約・電話予約で同じ時間が埋まることがあります（そのときは赤い印が付きます）。
- 台帳でHPBの予約を変えても、HPB（サロンボード）には反映されません。
- 合言葉が漏れた疑いがあるときは「合言葉を作り直す」→ Apps Script の SECRET を入れ直す。
- 受信アドレスが漏れた疑いがあるときは「ランダムなアドレスを作る」→ 保存 → サロンボードの通知先と Apps Script の PLUS_ADDRESS を入れ替える。
- 店長・オーナーが辞めたときは、合言葉と受信アドレスを両方作り直す。
