# 同意書・問診票（0025）　Run の直後にやる確認

0024 → 0025 を Supabase の SQL Editor で Run した直後に、オーナーが1回だけ行う確認です（10分ほど）。
Storage（ファイルの保存先）の権限は、本物の Supabase でしか確かめられないためです（監査 2026-11-11 M6）。
テストはテスト用のお客様（例：「テスト 太郎」）で行ってください。

## 0. Run の結果
- `0024_karte_page_images.sql` → 結果に「0024 OK：…」
- `0025_consent_documents.sql` → 結果に「0025 OK：…」
- Supabase の Storage に `consents` というバケットがあり、**Public ではない**こと

エラーが出たときは、そのまま Claude（04 自動化・システム）に画面の文を貼ってください。DB は途中まで変わらない作りです。

## 1. オーナー：テンプレを1つ登録する
1. 設定＞同意書・問診票 →「PDF・画像を選ぶ」
2. **見本（1ページ目）が出て、文字が欠けていない**ことを見てから「追加する」
   - 「パスワードや編集制限のかかったPDFは使えません…」と出たら、その PDF は使えません（制限を外すか、画像にして登録）
   - 黄色い注意（フォントが埋め込まれていません）が出たら、店の iPad の署名画面でも文字が全部見えるか確かめる

## 2. スタッフの役割のアカウント：1件署名して保存する（いちばん大事）
1. **役割が「スタッフ」のアカウント**で、店の iPad からログイン
2. テスト用のお客様 →「同意書を取る」→ 書類が全ページ表示される → チェック・署名 →「署名して保存」
3. 「保存しました」と出る →「PDFを開く」で **PDF が開き、最後のページに署名がある**こと

ここで「ファイルを保存する権限がありません」「署名済みPDFを保存できていません」などが出たら、そこで止めて連絡してください（Storage の権限の問題です。お客様には使わないでください）。

## 3. 閲覧のみのアカウント：見えるが、取れない
1. 役割が「閲覧のみ」のアカウントで同じお客様のページを開く
2. 「同意書・問診票」に 2 の書類が出て「開く」で PDF が開く
3. 「同意書を取る」のボタンは**出ない**

## 4. 店舗をまたいだ確認（使えない所では使えない）
1. 設定＞同意書・問診票 で、1 のテンプレの「使う店舗」を**1つの店舗だけ**にする
2. 画面左上で**別の店舗**に切り替え、お客様のページを開く →「同意書を取る」にそのテンプレが**出ない**
3. （別の会社のアカウントがある場合）そのアカウントでは、2 の書類もテンプレも**見えない**
4. 終わったら「使う店舗」を元に戻す

## 5. 後片づけと、書き換えできないことの確認
1. オーナーで、2 の書類の「取り消す」→ 理由に「動作確認」→ **「取り消し済み」の印が付き、書類は消えない**
2. SQL Editor で次を Run し、結果が下のとおりであること（署名済みの書類に「書き換え・削除」の方針が無い）

```sql
select policyname, cmd from pg_policies where tablename = 'consent_documents' order by 1;
-- consent_documents_ins | INSERT
-- consent_documents_sel | SELECT      ← この2行だけ

select action, actor_name, reason, at from audit_logs where table_name = 'consent_documents' order by at desc limit 5;
-- sign（スタッフの名前）と void（オーナーの名前・理由「動作確認」）が出る
```

## 決まり（スタッフに伝えること）
- お客様に iPad を渡す前に、**書類の文字が全部見えているか**を自分の目で確かめる。
  「書類を表示できません（署名は取れません）」と赤く出たときは、その書類では署名を取れません（店長に伝える → 書類を画像にして登録し直す）
- 署名済みの書類は、だれも書き換え・削除できません。間違えて取ったものは、オーナーが「取り消す」で印を付けます（書類は残ります）
- お客様を消すこと・統合することで、同意書が消えることはありません（統合すると、残した側のお客様に付いてきます）
