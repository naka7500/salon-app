# バックアップと復元（salon-app）

結論：**いまは自動のバックアップがありません。** 12/1 までに「A：Supabase を Pro にする」と「B：ファイル（カルテ画像・同意書）の書き出し」の2つを入れてください。
このページは、その入れ方と、いざというときの戻し方です。秘密（キー・パスワード）の値は、このページにもリポジトリにも書きません。

## 1. 何を守るか

| 守るもの | どこにあるか | 何で守るか |
|---|---|---|
| お客様・予約・売上・カルテの文字・LINEの記録 | Supabase の DB | A（Pro の毎日自動）＋ B（自分でも書き出す） |
| カルテ画像（`karte`）・署名済み同意書（`consents`） | Supabase の Storage | **B だけ**（Supabase の自動バックアップには、ファイルの中身は入りません） |
| プログラム | GitHub | push のたびに残る |
| 設定（Vercel の環境変数・LINE の鍵） | Vercel・LINE | パスワード管理に一覧を1部（下の 6） |

## 2. A：Supabase を Pro にする（社長・10分・月$25）

1. Supabase のダッシュボード → 左下の組織 → **Billing** → Pro にする
2. Database → **Backups** を開き、「Daily backups」に日付が並び始めるのを翌日確認する（7日分）
3. 戻すとき：同じ画面で日付を選んで **Restore**（戻している間はアプリが止まります。数分〜）

※Pro にすると「1週間使わないと止まる」こともなくなります。

## 3. B：自分でも書き出す（DB とファイル）

リポジトリの `scripts/backup/` に3本あります。どれも**読むだけ**で、本番には何も書きません。

| スクリプト | すること |
|---|---|
| `backup-db.sh` | DB を1つのファイル（`db_日時.dump`）に書き出す。おもな表の行数も `counts.txt` に残す |
| `backup-storage.mjs` | `karte`・`consents` の中身を全部フォルダに書き出す。一覧（大きさ・指紋）を `manifest.json` に残す |
| `restore-db.sh`・`restore-storage.mjs` | 戻す（**新しい空のプロジェクト**に向けて使う。本番には向けない） |

### 手で1回動かす（PC で）

必要なもの：Node.js 20以上、`pg_dump`（PostgreSQL のクライアント。Supabase と同じか新しい版）。

```
# 値は、その場で入力する（ファイルに書かない・履歴に残さない）
export SUPABASE_DB_URL='（Supabase ＞ Project Settings ＞ Database ＞ Connection string の Session pooler）'
export SUPABASE_URL='（https://….supabase.co）'
export SUPABASE_SERVICE_ROLE_KEY='（サービスキー）'

scripts/backup/backup-db.sh ./backup
node scripts/backup/backup-storage.mjs ./backup
```

できた `backup` フォルダを、**店の外の場所**（会社の Dropbox の、社長だけが見られるフォルダなど）に日付つきで移します。
お客様の個人情報と同意書がそのまま入っています。**共有リンクを作らない・スタッフ共有のフォルダに置かない**でください。

### 毎日自動で動かす（GitHub Actions・いまは無効）

`.github/workflows/backup.yml` に雛形があります。**いまは手で動かしたときだけ**動きます（自動では動きません）。

1. リポジトリを **Private（非公開）** にする（公開のままでは動かないようにしてあります）
2. GitHub → Settings → Secrets and variables → Actions → **New repository secret** で、次の名前の秘密を入れる
   - `SUPABASE_DB_URL`　`SUPABASE_URL`　`SUPABASE_SERVICE_ROLE_KEY`
   - `BACKUP_PASSPHRASE`（バックアップを暗号化する合言葉。長いものを作り、パスワード管理に控える。**無くすと開けられません**）
3. Actions → **backup** → Run workflow で1回動かす → 終わったら、その実行の画面の下「Artifacts」に `backup-…` があるのを確かめる
4. 毎日にするなら、`backup.yml` の `schedule` の2行の `#` を外す（毎日 03:30）
5. 残るのは14日分。月に1回は、最新の1つをダウンロードして Dropbox にも置く（GitHub のアカウントごと失ったときのため）

開け方：`gpg --decrypt backup-日付.tgz.gpg > backup.tgz`（合言葉を聞かれます）→ `tar xzf backup.tgz`

## 4. 戻し方

### ふだん（操作ミス・データが壊れた）＝ Supabase の画面から

Database → Backups → 戻したい日を選ぶ → Restore。**DB だけ**が戻ります（ファイルは消えていなければそのまま）。
戻した日より後に入った予約・会計は消えるので、先に「止まったときの手順」の紙の記録を用意してから。

### 最悪のとき（プロジェクトごと失った）＝ B のファイルから新しいプロジェクトへ

1. Supabase で新しいプロジェクトを作る（Tokyo）。**何も流さない**（空のまま）
2. DB を戻す
   ```
   export RESTORE_DB_URL='（新しいプロジェクトの接続文字列）'
   scripts/backup/restore-db.sh ./backup/db_日時.dump --yes
   ```
   最後に出る行数を、`db_日時.counts.txt` と見比べる（同じなら OK）
3. ファイルを戻す
   ```
   export RESTORE_SUPABASE_URL='（新しいプロジェクトのURL）'
   export RESTORE_SERVICE_ROLE_KEY='（新しいプロジェクトのサービスキー）'
   node scripts/backup/restore-storage.mjs ./backup --yes
   ```
4. Vercel の環境変数（`NEXT_PUBLIC_SUPABASE_URL`・`NEXT_PUBLIC_SUPABASE_ANON_KEY`・`SUPABASE_SERVICE_ROLE_KEY`）を新しいプロジェクトのものに替えて、Redeploy
5. Supabase → Authentication → 「Allow new users to sign up」をオフにする（新しいプロジェクトは既定でオン）
6. ログインして、お客様の数・今日の予約・同意書のPDFが開けるかを見る

`restore-db.sh` は、戻し先に表が1つでもあると止まります（まちがって本番に流さないため）。
戻すとき、Supabase の「新しい表は未ログインにも許す」という既定を先に外してから戻します（外さないと、守りが弱い状態で戻ってしまうため。スクリプトがやります）。

## 5. 復元の練習（1回・1時間）★まだやっていません

**戻せると確かめていないバックアップは、無いのと同じです。** 12/1 までに1回やってください（04部が一緒にやります）。

1. 3 の手順で書き出す
2. Supabase に練習用の無料プロジェクトを1つ作る
3. 4 の「最悪のとき」の 2〜3 をやる
4. 行数が合う・同意書のPDFが1つ開ける、を確かめたら、練習用プロジェクトを消す

確かめてあること（2026-11-15・手元の検証用DB）：書き出し → 空のDBに戻す → 行数が一致、表・関数・権限・行の守り（RLS）・トリガー・制約・バケットの定義が元と同じ。
**まだ確かめていないこと**：本物の Supabase 同士での復元（ログインの表・Storage の表の形が Supabase の版で違う場合がある）、Storage の書き出し・戻しの実行（偽の Storage での単体テストまで）。

## 6. 設定の控え（パスワード管理に1部）

値はパスワード管理（1Password など）に。ここには**名前だけ**。

- Supabase：プロジェクトのURL／anon key／サービスキー／DB のパスワード
- Vercel の環境変数：`NEXT_PUBLIC_SUPABASE_URL`・`NEXT_PUBLIC_SUPABASE_ANON_KEY`・`NEXT_PUBLIC_STORE_ID`・`SUPABASE_SERVICE_ROLE_KEY`・`CRON_SECRET`・（任意）`APP_BASE_URL`
- LINE（店舗ごと）：Messaging API のチャネルID・チャネルシークレット・アクセストークン／LINEログインのチャネルID／LIFF ID
- HPB連携：転送用の合言葉（設定＞HPB連携で作り直せる）
- バックアップの合言葉：`BACKUP_PASSPHRASE`

## 7. だれが・いつ

| すること | だれが | いつ |
|---|---|---|
| Supabase の Backups に昨日の日付があるか見る | 社長（または 04部の定期チェック） | 週1回 |
| GitHub Actions の backup が緑か見る | 同上 | 週1回 |
| 最新のバックアップを Dropbox へ | 社長 | 月1回 |
| 復元の練習 | 社長＋04部 | 最初に1回、その後は半年に1回 |
